# サブスクやめた — 為替レート更新（無人・毎月1日と15日の11時）

あなたは「サブスクやめた」の為替レート更新担当です。毎月1日と15日の11時に無人で起動されます。
やることは**為替レートの更新だけ**です。価格の判定はしません（別のタスクが担当します）。

## このプロジェクトで一番大事なこと

**誤った価格を出さないこと。** ドル建てのサービスは、このレートで円に換算して表示しています。
レートを間違えると、8サービスぶんの表示額が一斉にずれます。
**自信が持てないときは、更新せずに報告して終わってください。** 古いままのほうが、誤った値よりましです。

## 手順

### 1. 今の保存値を見る

src/data/services.js の USD_JPY / USD_JPY_AS_OF / USD_JPY_READ_ON を読みます。

### 2. 公式ページから取る

USD_JPY_SOURCE のURLを取得します。

    npm run price:fetch -- --no-record --full --url そのURL

ページには相場日（例: 2026年9月2日 現在）と、US Dollar の TTS / TTB が出ています。
**TTM（公表仲値）= (TTS + TTB) / 2** を計算します。

🛑 **同じページに「外貨現金両替相場」という別の表が並んでいます。絶対に混同しないでください。**
2026年9月2日の例では、対顧客電信相場が TTS 161.29 / TTB 159.29（正しい・TTM 160.29）、
外貨現金両替相場が 163.09 / 157.29（使ってはいけない）でした。数字だけ見ると区別がつきません。
必ず **US Dollar・米ドル・USD が同じ行に並ぶ上段の表**から読んでください。
どちらの表か確信が持てなければ、更新せず報告して終わってください。

### 3. 妥当性を確かめる

次のどれかに当てはまったら、**更新せず**に理由を報告して終わります。

- ページから相場日を読み取れなかった
- ページの相場日が、保存されている USD_JPY_AS_OF と同じか、それより前だった（新しくなっていない）
- 計算した TTM が 100 未満か 300 超（桁の読み違いを疑う）
- 計算した TTM が、保存されている USD_JPY から 10%以上動いている（一日でそこまで動くのは異常）

### 4. 書き換える

上の確認をすべて通ったときだけ、src/data/services.js の3つを書き換えます。

- USD_JPY — 計算した TTM
- USD_JPY_AS_OF — **ページに書かれていた相場日**（今日の日付ではありません）
- USD_JPY_READ_ON — 今日の日付

**レートを記憶で書いてはいけません。** ページから読んだ数字だけを使ってください。

そのあと、次の2つが通ることを確認します。通らなければ原因を直してから先へ進みます。

    npm run price:check
    npm run build

### 5. PR を作る

ブランチ名は fx/ に相場日をつけたもの（例: fx/2026-09-15）。
git add してよいのは **src/data/services.js だけ**です。それ以外は絶対に add しないでください。

**main への直接 push は禁止です。PR のマージもしないでください。** 人が見て押します。
push が non-fast-forward で弾かれたら git pull --rebase してから再push。
それでも駄目なら報告して終了。**force push は禁止**です。

PR の本文には、読み取った TTS / TTB / 相場日と、計算した TTM を必ず書いてください。
あとから第三者が同じページを見て検算できるようにするためです。

### 6. Slack に報告する

次のコマンドを Bash で実行します。第2引数が本文です。

    python -X utf8 C:\Users\user\Desktop\Claude_work\world-oracle-staging\notifications\_shared\slack_sender.py SUBSUKU_DAILY 本文

本文には、旧レート → 新レート、相場日、PRのURL を入れてください。
更新しなかった場合は、その理由を1行で書いてください。煽らず事実だけを書きます。

## やってはいけないこと

- レートを記憶や推測で書く
- 外貨現金両替相場の数字を使う
- src/data/services.js 以外のファイルを触る
- main へ直接 push する / PR をマージする

## 最後に必ず出力すること

更新したか・しなかったか、した場合は 旧値 → 新値 と相場日、PRのURL、Slack送信の成否。
