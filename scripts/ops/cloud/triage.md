# 【クラウド】3日ごとの棚卸しの基準（当番 daily.md が、3日に1回の巡回をこの基準で回す）

あなたは「サブスクやめた」の運用棚卸し担当です。最初に scripts/ops/cloud/COMMON.md を読み、そのルールに従ってください。
**溜まって誰も気づかなくなったものを見つけて、直せるものは直す**のが仕事です。

## 手順

### 1. 機械の点検を走らせる

    node scripts/ops/cloud_check.mjs --days 3 --seo

（未マージPR・為替の鮮度・為替PRの矛盾・本番と main の差・本番サイトの生死・価格監視の記録・SEO健全性）

### 2. 対応が要る指摘が無い（exit 0）なら

**何もせず、Slack にも送らずに終了する**（毎回鳴ると肝心な日に効かなくなる。週次レビューが必ず1本送る）。

### 3. 指摘があれば、直すか・回すかを決める

基準は scripts/ops/triage_prompt.md の「直してよいもの／直してはいけないもの」と同じ。（冒頭の「クラウドへ移行」の注意書きは PC 向け。クラウドではその下の基準の部分だけを使う）加えて：

- 価格のPRを裏取りする時、クラウドは米国から接続している（COMMON.md）。日本の価格を確かめられない
  サービス（`SUBSUKU_CLOUD=1` の price:fetch でも円が読めないもの）はマージせず「クラウドから確認できず」と回す。
- 同じ相場日で値が食い違う為替PRが複数あれば、どれも採用せず scripts/ops/cloud/fx.md の手順で一次情報から取り直して1本にまとめる。
- 「価格監視の記録が止まっている」：朝 7:47 の価格の当番（price.md）が動いていない。その日まだ巡回していなければ price.md の手順で1回分をやってよい。

### 4. 直したら確かめる

    npm ci   # 未実行なら
    npm run price:check
    npm run build

両方通らなければ、直した内容を元に戻してから報告する。**壊れたまま置かない。**
push したら COMMON.md の「本番に出たかの確かめ方」で本番反映を確認する。

### 5. Slack に1本報告する

点検で出た指摘の件数と中身（1行ずつ）／自分で直したもの（何を・なぜ直してよいと判断したか）／
直さず回したもの（なぜ・俊雄さんに何をしてほしいか）。

## 最後に必ず出力すること

点検の指摘件数、直した件数と内訳、回した件数と理由、Slack送信の成否。
