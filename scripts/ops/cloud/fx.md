# 【クラウド】為替レート更新（毎月1日と15日・11時台 日本時間）

あなたは「サブスクやめた」の為替レート更新担当です。最初に scripts/ops/cloud/COMMON.md を読み、そのルールに従ってください。
やることは**為替レートの更新だけ**です。価格の判定はしません。

ドル建てのサービスは、このレートで円に換算して表示しています。レートを間違えると、
ドル建てサービスの表示額が一斉にずれます。**自信が持てないときは、更新せずに報告して終わってください。**
古いままのほうが、誤った値よりましです。

## 手順

### 0. 時刻を確かめる

`TZ=Asia/Tokyo date` で日本時間を見る。**10:30より前なら何もせず終了**（公表仲値の発表は10時頃。
発表前に取ると前営業日の値を掴み、同じ相場日に別の値が入る）。Slack にも送らない。

### 1. 今の保存値を見る

src/data/services.js の USD_JPY / USD_JPY_AS_OF / USD_JPY_READ_ON / USD_JPY_SOURCE を読む。

### 2. 公式ページから取る

USD_JPY_SOURCE のURLを取得する（文字コードは Shift_JIS(cp932)）。

    curl -sS "<USD_JPY_SOURCE>" | iconv -f CP932 -t UTF-8

ページには相場日（例: 2026年9月2日 現在 / As of October 16, 2026）と、US Dollar の TTS / TTB が出ている。
**TTM（公表仲値）= (TTS + TTB) / 2** を計算する。

🛑 **同じページに「外貨現金両替相場」という別の表が並んでいる。絶対に混同しない。**
2026年9月2日の例では、対顧客電信相場が TTS 161.29 / TTB 159.29（正しい・TTM 160.29）、
外貨現金両替相場が 163.09 / 157.29（使ってはいけない）だった。数字だけ見ると区別がつかない。
必ず **US Dollar・米ドル・USD が同じ行に並ぶ上段の表**から読む。確信が持てなければ更新せず報告して終わる。

### 3. 妥当性を確かめる（1つでも当てはまれば更新しない）

- ページから相場日を読み取れなかった
- ページの相場日が、保存されている USD_JPY_AS_OF と同じか、それより前（新しくなっていない）
- 計算した TTM が 100 未満か 300 超（桁の読み違いを疑う）
- 計算した TTM が、保存されている USD_JPY から 10%以上動いている

### 4. 書き換える

確認をすべて通ったときだけ、src/data/services.js の3つを書き換える。

- USD_JPY — 計算した TTM
- USD_JPY_AS_OF — **ページに書かれていた相場日**（今日の日付ではない）
- USD_JPY_READ_ON — 今日の日付（日本時間）

そのあと次の2つが通ることを確かめる（`npm ci` が済んでいなければ先に実行）。通らなければ原因を直してから進む。

    npm run price:check
    npm run build

### 5. main へ直接コミットして push する（2026-09-23 俊雄さん承認・自動デプロイ）

PR で止めると人が押すまで古いレートが出続ける（2026-09-02〜09-22 の20日間据え置かれた）。
手順3を通った新しいレートは検証済みなので、人のゲートを置かずに出す。

git add してよいのは **src/data/services.js だけ**。

    git add src/data/services.js
    git commit -m "為替レート更新: USD_JPY <旧値> → <新値>（<相場日>相場日）" -m "TTS <値> / TTB <値> → TTM=(TTS+TTB)/2=<値>" -m "クラウドの定期タスクで更新" -m "Co-Authored-By: Claude <noreply@anthropic.com>"
    git push origin main

### 6. 本番に出たか確かめる

COMMON.md の「本番に出たかの確かめ方」どおり。build.json の commit が今回のコミットになり、
実ページ（ドル建てサービスのページ。services.js の USD_PRICED にあるもの、例 https://sabusuku-yameta.com/service/claude-pro/ ）の換算額が
新しいレートに合っていることを確かめる。error なら報告して終了（再更新はしない・次の区切りを待つ）。

### 7. Slack に1本報告する

旧レート → 新レート、相場日、コミットURL、本番の確認結果。更新しなかった場合はその理由を1行で。

## 最後に必ず出力すること

更新したか・しなかったか、した場合は 旧値 → 新値 と相場日、コミットSHA、本番の確認結果、Slack送信の成否。
