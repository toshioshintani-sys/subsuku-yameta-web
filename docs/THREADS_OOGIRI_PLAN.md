## 1. 作戦の中身

### 型（全部テキスト・テーマはサブスク／固定費／解約／お金に固定）
| 型 | 割合 | 例 |
|---|---|---|
| **お題投げ**（返信で読者が大喜利する） | 4割 | お題：サブスクの解約ボタン、どこに隠されてた？いちばんひどかった場所を教えてください |
| **一言ボケ**（あるあるを一言で刺す） | 4割 | 毎月引き落とされてるのに一度も会ったことない。それがサブスク。もはや文通相手 |
| **選手権・比喩**（並べて笑う） | 2割 | 「本当に解約しますか？」って聞かれると、なんで少し申し訳ない顔しちゃうんだろう。相手、ボタンだよ |

### 守ること（ブランドの決まりとの両立）
- **笑いの向き先は「自分（当事者）」と「仕組み」**。企業名・サービス名・実在の人は出さない（「業者を殴って業者で稼ぐ」偽善を避ける）。
- **値段・条件の数字は書かない**（笑いのために盛る誤報を構造的に防ぐ）。書くなら公式で確かめた値だけ。
- 強さは kokuchi-plan の物差しで **3以下**。人格攻撃・差別・下品は不可。
- **本文にリンクを入れない**（真面目な宣伝に見える＋外部リンクは伸びにくい）。サイトへはプロフィールのリンクだけ。
- 返信への返信は自動でしない（他人への自由生成・自動送信は2026-06-07に却下済み）。

### 量とタイミング
- 1日2本（昼 12時台・夜 21時台）×3週間＝**42本**。

### 作り方（ネタ切れと質の担保）
- 毎週月曜の週次レビューで、運用当番が**20本の候補**を作る → 採点表（笑えるか／当事者視点か／数字・企業名なしか／強さ3以下か）で**14本**に絞る → `scripts/threads/queue.json` に積む。
- 伸びた投稿（下の指標）の型を翌週の候補づくりに反映する。

### 測るもの（判定の材料）
- 投稿ごとの **表示数・いいね・返信・再投稿**（Threads のインサイト）
- プロフィールのリンクのクリック／GA4 の `utm_source=threads`

## 2. 判定と撤退ライン（先に決める）

| 3週間・42本の結果 | 次の一手 |
|---|---|
| **1本でも表示1,000超え**、かつ前回より表示の中央値が上がった | 形式説が正しい → 第2段階へ（伸びた投稿にだけ返信でサイト誘導・画像は「衝撃の一瞬」型を試す） |
| 1,000超えなし・でも反応（返信・いいね）は前回より明らかに増えた | 1回だけ型を組み替えて3週間延長 |
| 1,000超えなし・反応も変わらない | **形式説も否定** → Threads を正式に止めて lessons に記録（PR #38 の「discovery型チャネルに投資しない」を確定させる） |

前回の撤退ライン（100本で1本も1,000超えなし）より早く判定する。前回の49本はすでに「真面目な形式」で消化済みのため。

## 3. 引っ越しとの関係（技術）

- 投稿はクラウドで動かす。**秘密（アクセストークン）をクラウドに置く場所が要る。**
  案：Netlify の「定時に動く関数」で投稿し、トークンは Netlify の環境変数（秘密）、延長後のトークンと投稿位置は Netlify Blobs（Netlify 内の保管庫）に置く。
  トークンが git にも Claude の会話にも出ない。投稿の中身（queue.json）だけをリポジトリで管理する。
- **俊雄さんの操作が要るのは最初の1回だけ**（約10分）：
  1. Meta の開発者画面で権限 `threads_manage_insights` を追加し、トークンを作り直す（インサイトを測るため）
  2. そのトークンを Netlify の環境変数 `THREADS_ACCESS_TOKEN`（秘密）に貼る（`THREADS_USER_ID` は既知）
- PC の Threads 関連タスク（4コマ 12:00・返信監視 20:30）は、この作戦では使わない → 止める。

## 4. stress-test の要約

**残った否定（つぶし切れないもの）**
1. バズってもサイト訪問・収益につながるかは未検証（致命ではない：3週間の試験で測る）
2. AI が作る大喜利が本当に面白いかは出してみないと分からない（採点表＋伸びた型の反映で緩和。最初の週は俊雄さんが候補を見て「これは無い」を外すと精度が上がる）
3. 無人の自動投稿が一度でも滑る（不快・炎上）とアカウントの信頼が傷つく（数字・企業名・人を出さない／強さ3以下／緊急停止スイッチで緩和）

**やる理由**
1. 前回の不発の原因が2択のまま。**形式を変えて試さないと、場所が悪いのか形式が悪いのか永遠に分からない**
2. 費用はほぼゼロ（外部支払いなし・クラウドの当番が作る・アカウントとアプリは作成済み）
3. フォロワーゼロでも外に届く仕組みの場は Threads くらい（検索経由の流入は今も薄い）
4. 3週間で白黒がつき、失敗しても撤退コストが小さい（投稿は消せる・サイト本体は無関係）

**判定：設計を直して進める**（残った否定は致命的ではない。3つとも上の設計に対策を組み込み済み）

## 方針の更新（2026-10-17 夜・俊雄さん決定）— こちらが最新。上の本文と食い違う所はこちらを優先

> 「とにかくスレッズでバズらないとなにも始まらない。面白い話を投稿しているこの人なんなんだろうとアカウントを見に行ったらリンクがあるのが理想。ネタはサブスクに寄せる必要まったくなし。」

1. **Threads の投稿はテーマ自由。サブスクに寄せない。** 寄せる先は「分析で出てきた、伸びる型」（500件の分析の結果で決める）。
2. **投稿にはリンクを載せない。** サイトへの入口はアカウントのプロフィールのリンク1つだけ。「この人なんなんだろう」と見に来た人が、リンクから飛ぶ。
3. **アプリ内に同じ内容のページ（案：「ひとこと」`/hitokoto`）を作る。** 目立たせない（ナビに出さない。フッターとサイトマップだけ）。構成は4段：
   ネタ（Threadsに出す文面）→ 示唆（ネタの核の心理・構造を一言で）→ 本体（それがサブスク・固定費でどう現れるかの説明。数字は公式で確認できたものだけ・両論併記）→ 次の一手（解約手順・棚卸しツールへの静かな案内）。
   **サブスクへの橋はこのページ側（示唆と本体）でかける。** ネタの側ではかけない。橋が一言で架からないネタは、ページを作らず Threads だけに出してよい。
4. 守ること（ネタがサブスクと無関係でも変わらない）：企業名・実在の人・金額の数字を出さない／人格攻撃・差別・下品は不可／強さは3以下／緊急停止スイッチを持つ。
5. プロフィール（自己紹介文・リンク先）は、笑いに来た人が見て違和感のない文面にする。リンク先は `/hitokoto`（一覧）。
6. 500件の分析が終わるまで、型は決めない（俊雄さんの決まり）。先に作るのは**ページの仕組み**（一覧・1本ごとのページ・台帳から作る流れ）だけ。
