# Threads のバズ投稿を API を使わずに集める方法（調査・2026-10-17 18:43〜）

> **目的（変えない）**：すでに世の中にある日本の Threads のバズ投稿を **500件以上** 集め、傾向を分析する。
> 自分の投稿の試験に置き換えない（2026-10-17 俊雄さんの絶対命令）。
> この文書は「集め方の選択肢」だけを並べる。どれを使うかは俊雄さんが決める。

調べた範囲：日本のツール／海外の分析ツール／公開データセット／日本と海外の分析記事／Threads自体・検索エンジン・埋め込み／収集業者／Chrome拡張／ニュース記事／大喜利の情報源。
調査役のべ15人＋私の検索。主な結論は、別の調査役が反証の立場で確かめ直した。規約は原文（日本語版）で確かめた。

## 2. 各方法の詳細

### A. ねとらぼの「Threads」タグ（いちばん確実）
- タグのページ：https://nlab.itmedia.co.jp/relatedtags/threads/ （1ページ約50件・8ページまで＝約387件。9ページ目は無い・2026-10-17 実測）
- 最近は2週間で約50件増えている（1ページ目＝10/2〜10/17）。新しい記事を待てば約5週間で500件を超える計算。
- **私が23記事を機械で読んだ結果**（2〜8ページから・2026-10-17）：
  - 23件すべてが Threads の投稿の記事で、23件すべてに元の投稿へのリンクがあった。
  - 表示数かいいね数が読み取れたのは16件（約7割）。表示数16件・いいね数12件。値は2万3000〜230万回表示、1,100〜8万2000いいね。
  - 残りの7件のうち少なくとも1件は「閲覧数は7万8000回を突破し、“いいね！”は9800件を超えています」という書き方で、読み取りの型から漏れていた。数字がまったく無い記事（「反響を呼んでいる」だけ）もある。**実際に数字が付いているのは7〜8割**と見る。
  - 別の調査役が読んだ記事も同じ形だった（例：35万回・4,200いいね、130万回・4.4万いいね）。
- 数字は「記事を書いた時点」の値で、「○万回以上」のような概数。書き方が記事ごとに違うので、読み取りの型は何通りも用意する（上の取りこぼしで確認済み）。
- **件数の見通し**：記事は今387件。数字つきに限ると約270〜310件。最近は月に約100件増えている（その7〜8割が数字つき）ので、**数字つき500件に届くのは約3か月後（2027年1月ごろ）**の計算。記事だけで数えた500件なら、約5週間後（11月下旬）。
- robots.txt に禁止なし（https://nlab.itmedia.co.jp/robots.txt ）。記事サイトマップもある。
- 保存は事実だけにする（Threads のURL・表示数・いいね数・日付・題材の短いラベル）。記事の本文・見出し・写真は保存も公開もしない。
- **偏り**：題材は家族・子ども・弁当・ペット・お店の驚き・珍しい物の写真がほとんど。**文字だけの投稿は見つからなかった**（調査役が開いた記事は10/10が写真つき）。
- ほかの媒体：Hint-Pot・まいどなニュースも Threads の投稿を記事にするが、タグのページが無く、数を稼ぎにくい。

### B. Apify（収集業者）のキーワード検索
- 候補：webdata_labs/threads-scraper（https://apify.com/webdata_labs/threads-scraper ）
  - ログイン不要。1回の検索で約20件（ページ送りなし）。
  - 取れる項目：本文・URL・日時・ユーザー名・いいね・返信・再投稿・引用。表示数はほぼ取れない。
  - 1,000件あたり3ドル。利用者221人・成功率98.5%。
  - 日本語で動くかは未検証。
- 人気順を指定できるのは dressy_europium/threads-toolkit（`top`）だけ。1回約10件・1,000件あたり5ドル。
- 見積もり（調査役の推定）：サブスク・節約・固定費・家計・お金・解約・あるある などの組み合わせで80〜100検索 → 約2,000行 → 約6ドル。重複と人気の低い投稿を除いて500件が残る見込み。
- **必要なこと**：俊雄さんが Apify に登録して支払い方法を入れる（アカウント作成と支払いは Claude はできない）。最初に5〜10検索（1ドル未満）で日本語が取れるかを試す。
- ログイン情報（sessionId）を入れる業者は使わない（自分のアカウントが止められる危険）。

### C. Bright Data の作り置きデータ
- https://brightdata.com/products/datasets/threads
- 投稿 約8,500万件。項目に表示数・いいね・コメント・再シェア・本文。
- 最低250ドル（10万件）。絞り込んだ件数だけ課金。無料サンプル1,000件あり（受け取りには登録が要る見込み）。
- **日本語・日本で絞れるかは未確認**（項目一覧の全体が読めなかった）。サンプルで日本語の割合を見てから判断する。

### D. Chrome拡張（人が見た画面を記録する）
- Threadlytics（https://chromewebstore.google.com/detail/khfnmiondbedflonieecjbkiopmpndgm ）：「検索かプロフィールから最大1,000件」と自称。CSV出力。仕組み（自動スクロールか）と価格は不明。
- Threads Data Collector（https://chromewebstore.google.com/detail/ohpcddkbfpemigbobdkjhigganknfjce ）：閲覧中に届いたデータを読むだけ、と自称。利用者7人。

- どれも俊雄さんがログインした状態で動く。止められた報告は見つからないが、無いとも言えない。

### E. 人の手で集めてもらう
- クラウドワークス・ランサーズで「Threads の検索（人気）で、指定キーワードの投稿のURL・本文・いいね・返信・再投稿を表に転記」と依頼する。
- 普通の閲覧なので規約の問題は無い。文字の大喜利も拾える。
- 似た依頼の実例（ランサーズ・すべて募集終了）：
  - TikTokのインフルエンサー100名のリスト（7項目）が2,700円＝1件約27円（https://www.lancers.jp/work/detail/5585727 ）
  - 海外ショート動画のURL集めが1件100円（https://www.lancers.jp/work/detail/5282626 ）
  - 項目が1つだけの調査が1件5円（https://www.lancers.jp/work/detail/5617361 ）
- 発注者の手数料：ランサーズは契約金額の5%（税込5.5%）（https://www.lancers.jp/faq/C1013/508 ）。クラウドワークスは未確認。
- 見積もり（調査役の推定）：1件3〜5分×500件＝25〜42時間。**1件100〜200円なら5万〜10.6万円**（手数料込み）。1件30〜50円では集まりにくいか、質が落ちる見込み。
- 質の守り方：
  - 投稿URLを必須の列にし、重複を除く
  - 最初の20件を試しに納品してもらい、基準に合うか確かめてから残りを頼む
  - 承認した件だけ払う
  - 10〜20%を発注者がURLで確かめる
- 私の作業：依頼文と記入表の作成、納品された表の検算（URLの重複・数字の書式・抜き取りの確認）。発注と支払いは俊雄さん。

## 3. 規約と法律について（言い過ぎないように）

Meta 利用規約（日本語版・「2025年1月1日から適用」・第3条 3.2・https://www.facebook.com/terms.php ）の原文：
- 自動収集：「弊社から事前の許可を得ることなく、自動化手段を用いて弊社製品のデータにアクセスしたり、データを取得したりすること……は禁止されています。」「このような自動的なアクセスまたは取得が、Facebookアカウントにログインしているときに実行されたかどうかを問いません。」
- **データの売買**：「プラットフォーム利用規約に定められた場合を除き、弊社または弊社のサービスから取得されたデータを販売、ライセンス供与、または購入してはなりません。」こちらも、ログイン中に取得されたかどうかを問わない。
- 違反したときの措置として、コンテンツの削除・アクセスの制限・アカウントの停止が定められている。
- Instagram 利用規約と Threads の補足規約の本文は、ページが読めず未確認（Threads は Instagram の規約に従う）。

米国の裁判（Meta 対 Bright Data・2024年1月）では、ログインせずに公開データを集めたことは規約違反にあたらない、と判断された。Meta は訴えを取り下げている（https://www.fbm.com/post/102kqw7/ ）。ただし次の限界がある。
- 対象は Facebook・Instagram で、Threads ではない。
- 判断は改定前の規約についてのもの。
- 争点は契約だけで、ほかの法律は対象外。
- 判断されたのは「集めた業者」について。上の売買の禁止は、**買う側の私たち（Meta の利用者）にかかる約束**。

**つまり：**
- **B（Apify）・C（Bright Data）は、業者から Threads のデータを買うことになる。** 規約の「購入してはならない」にそのまま当たる。業者のほうは裁判で勝っているが、買う私たちの約束は別の話。違反した場合に止められうるのは、俊雄さんの Facebook・Instagram・Threads のアカウント（@sabusuku.yameta を含む）。
- D（Chrome拡張）は、俊雄さんのログイン中のアカウントで自動収集をすることになり、条文にそのまま当たる。
- 規約に触れないのは A（ニュースサイトを読む）だけ。
- E（人が普通に閲覧して転記する）は自動収集ではない。ただ「サービスから取得されたデータの購入」の禁止は、自動かどうかに限っていない。集めてもらった表にお金を払うことがこれにあたるかは、解釈が分かれる（人の作業への支払いと見るか、データの購入と見るか）。
- 「正直」を売りにするサイトとして、どこまで許すかは俊雄さんが決める。

## 4. 既にある分析（数字は仮説の材料・500件の代わりにはしない）
- Meta 日本法人（2026-07・3周年の説明会）：日本はテキストだけの投稿の割合が世界平均より高い。表示の半分超が返信から来ていて、日本はその傾向がより強い（https://www.watch.impress.co.jp/docs/news/2121668.html ）。
- Buffer（世界・Threads 12.8万投稿）：投稿者がコメントに返信した投稿は、返信しない投稿よりエンゲージメントが平均約42%高い。因果は未証明（https://buffer.com/resources/threads-comments-engagement/ ）。
- Buffer（世界・4,500万投稿）：Threads の形式別の中央値は、動画5.55%・画像4.55%・テキスト2.79%・リンク2.34%（https://buffer.com/resources/data-best-content-format-social-media/ ）。
- ちよこさんの note（2025-02）：バズ投稿30件（いいね1,000以上かつ10万インプレッション以上）を17の型に分類。型の一つが「大喜利」（https://note.com/r_chiyoko/n/n1becc71eebd0 ）。
- 個人の154投稿の実測：上位1本が全表示の38.5%。外部リンク付きの投稿は不利（https://note.com/samurai_worker/n/n9df31501304a ）。
- Threads 自体の「話題のトピック」は、見る人ごとに変わらない日本全体のトレンド（https://about.fb.com/ja/news/2026/03/threads-trends/ ）。ただし投稿の数字は出ない。

## 5.2 追加調査（19:09〜・文字の大喜利に絞って）

**文字だけの大喜利を、規約に触れずに数字つきで集められる情報源は、見つからなかった。**

- **ねとらぼ以外の媒体**：Threads専用のタグを持つ媒体は無かった。
  - ほ・とせなNEWS：Threads の記事が多く、表示数が付く（例：74万表示・254万表示）。いいね数は記事によって載らない。元の投稿へのリンクは無く、投稿者の ID だけ。「SNSで話題」タグ https://www.hotosena.com/article/tag/11033141 （Threads に限らない）。robots は /wp-admin/ のみ禁止。夫婦の会話ネタの記事もある（https://www.hotosena.com/article/15541632/ ）。ねとらぼの次に数を足せる。
  - まいどなニュース・Hint-Pot・Jタウンネット・オトナンサー：Threads の記事はあるが少なく、大半は X。タグも無い。
  - どの媒体も写真の投稿が中心。文字だけの大喜利を記事にする媒体は無かった。
- **人が選んだ一覧**：投稿へのリンクやいいね数がついた一覧は、1件も無かった。
  - よしもとThreads王決定戦は2024年の開催で、約130組が応募した（https://prtimes.jp/main/html/rd/p/000003654.000029501.html ）。予選は吉本の公式 Threads での投票。記事に載っているのは決勝10組の名前だけ。優勝作は動画。
  - Meta 日本法人のポッドキャスト「Threadsのあの人」で、これまでに紹介されたのは2アカウント。
  - ITmedia の記事（https://atmarkit.itmedia.co.jp/ait/articles/2510/31/news007.html ）は、Threads での失敗自慢の「ネタ合戦」を取り上げている。日本の Threads で大喜利のような遊びが盛んだ、という観察の裏付けにはなる。ただし投稿の一覧ではない。
  - Meta 日本法人自身が、2024年の年末に Threads で「お題」に答えるイベントを開いた（https://about.fb.com/ja/news/2024/12/threads_eoy_event/amp/ ）。
- **検索エンジン**：Threads の大喜利投稿そのものは、検索結果にほとんど出てこない。
- **ねとらぼの Threads タグは、2025年11月6日の記事から始まる**（8ページ目で最も古い記事・実測）。それより前の記事は、タグからはたどれない。
- **規約の「データの購入」の禁止**：人の手による調査代行が含まれるかを論じた解説や判例は、見つからなかった。Meta 対 Bright Data では、「Meta の利用者が買うのは規約違反で、業者はそれをそそのかした」という趣旨の Meta の主張（不法干渉）が残っていた（https://www.fbm.com/technology/publications/major-decision-affects-law-of-scraping-and-online-data-collection-meta-platforms-v-bright-data/ ）。Meta は買う側の違反も問題にしている。
- **ニュース記事から数字と URL だけを取る**：事実は著作物ではないので危険は低い、という整理（記事の文章・写真は使わない）。
- **営利の事業者が使える、Meta 公式の研究用の経路**：無かった（Content Library は非営利の研究機関だけ）。

## 6. 私の判断（決めるのは俊雄さん）
1. **A（ねとらぼ）はすぐ始められる。**規約の問題が無く、元の投稿へのリンクが必ず付き、私が機械で集められる。ただし数字つきで500件そろうのは約3か月後（今ある分は約270〜310件）。
2. ただし A だけでは「文字の大喜利」が抜ける。俊雄さんの観察の中心はそこなので、**A だけで結論を出すと偏る。**
3. 文字の大喜利を数字つきで集める道で、規約に一番近いのは E（人の手・5万〜10万円）。ただし「データの購入」にあたるかの解釈は残る。B〜D は Meta 規約 3.2 の条文にそのまま当たる（§3）。

決めてほしいこと：
- A を今すぐ始めてよいか
- 文字の大喜利の分をどう集めるか：
  - E（人の手）で見積もりを取る
  - 規約違反を承知で B〜D を使う
  - 集めない
